# Applicable counterexamples checks

Apply the checks below addressed to your assigned pass. They are direct review obligations, not instructions to delegate or spawn agents.

**Independent challenge required in both Toolkit and Spec agent prompts:** Claim inventories and new tests are leads, not a complete list of possible failures. For a changed bound, parser, allocation, or panic guard, construct concrete untested input shapes, including nested or malformed values and an alternate destination type where applicable. Calculate the bound against the actual minimum encoded bytes and allocation, and trace component indexing and nil/interface paths to the consumer. If the fix limits peer-controlled allocation, compute the maximum allocation before a later decoder rejects each shape and its ratio to payload bytes; compare that ratio with the PR's stated resource goal. A later error or linear big-O growth does not make a large amplification harmless. Verify any claimed companion or upstream input rejection in the pinned checkout's parser; do not assume it exists because the PR body mentions another change. Cite the rejecting branch for each shape or report the failure; do not call the code sound based only on the supplied tests. For a new wait, trace one in-flight producer without an actual configured timeout or cancellation: name what resolves its future, what shutdown or abort would unblock it, and whether the changed order places that action after the wait. Compare an active front entry and a queued successor separately; a previous close that could stall on one schedule does not prove the new wait cannot stall on an additional one. Do not call the old flush equivalent without checking whether it reaches the same unblocker before waiting on each entry.
