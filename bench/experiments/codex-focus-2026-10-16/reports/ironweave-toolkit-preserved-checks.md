## Toolkit

- **[P2] Queue drain can prevent shutdown from unblocking a write** — [src/rpc/rpc.cc:565](/tmp/ad-codex-focus-20261015/ironweave-toolkit-preserved-checks/src/rpc/rpc.cc:565). After the sink closes, a compressor can enqueue a sufficiently large control frame whose socket write blocks because the peer stops reading. Reading the peer’s stream EOF then enters the new drain and waits for that write before closing the output. At base, with empty local buffers, `output_stream::close()` can reach the POSIX sink’s `shutdown(SHUT_WR)` without awaiting that independent write. Head delays this unblocker and the subsequent `stop()`. Peer progress or an independent abort can rescue the connection, but normal stream closure can now hang on this additional schedule.

- **[P2] New sink wrapper fails to compile with API levels below 9** — [tests/unit/rpc_test.cc:1883](/tmp/ad-codex-focus-20261015/ironweave-toolkit-preserved-checks/tests/unit/rpc_test.cc:1883). The unconditional span-based `put()` override does not match `data_sink_impl` at API level 8, where `put(net::packet)` remains pure virtual. Its forwarding call also lacks a matching overload. The wrapper is therefore abstract and `rpc_test` cannot compile in this supported configuration. The existing loopback sink handles both APIs conditionally.

- **[P2] Regression test can pass through the old error guard** — [tests/unit/rpc_test.cc:2017](/tmp/ad-codex-focus-20261015/ironweave-toolkit-preserved-checks/tests/unit/rpc_test.cc:2017). While the client’s close is parked, the server can consume the client’s EOF and close its transport. The client receive loop can consequently set `_error` before the hook runs. The hook then fails through the pre-existing guard, with no late write, even without `_stream_closing`. The test’s gate and assertions do not distinguish this permitted schedule from exercising the new guard.

- **[P3] Successful sends satisfy the claimed refusal check** — [tests/unit/rpc_test.cc:2016](/tmp/ad-codex-focus-20261015/ironweave-toolkit-preserved-checks/tests/unit/rpc_test.cc:2016). The hook may complete successfully without failing any assertion; the catch does not establish that `closed_error` occurred. An implementation that silently discards closing-time sends and returns success would pass, despite violating the promised error result. The final assertion checks only writes after close.

- **[P2] New transition wait has no local failure bound** — [tests/unit/rpc_test.cc:2011](/tmp/ad-codex-focus-20261015/ironweave-toolkit-preserved-checks/tests/unit/rpc_test.cc:2011). The condition-variable wait observes only `close_entered`, without a timeout or an alternative failure completion. If the expected close is not reached, the test cannot proceed to release or cleanup. Both close producers were considered; this is missing local failure protection, not a claim that neither can signal. The repository’s external timeout defaults to 300 seconds and is configurable.

- **[P2] Fatal assertion bypasses required sink cleanup** — [tests/unit/rpc_test.cc:2000](/tmp/ad-codex-focus-20261015/ironweave-toolkit-preserved-checks/tests/unit/rpc_test.cc:2000). If the negotiation-count assertion fails, unwinding destroys the already-created sink before `close()` runs. `sink_impl::~sink_impl()` asserts that the connection’s sink flag is closed, so an ordinary test failure can abort the process. The outer deferred client stop runs after this local destructor.

## Standards

- **[P2] Negotiation mutates a factory owned by another shard** — [tests/unit/rpc_test.cc:1957](/tmp/ad-codex-focus-20261015/ironweave-toolkit-preserved-checks/tests/unit/rpc_test.cc:1957). `server_factory` is constructed on the test shard and shared through server options. With two shards, the loopback acceptor assigns the stream connection to shard 1, where negotiation mutates that factory’s `hooks` vector. Negotiations being serialized does not establish compliance with that ownership requirement; this finding does not allege concurrent vector access.
